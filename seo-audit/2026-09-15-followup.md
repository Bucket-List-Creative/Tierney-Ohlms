## New finding

### P0-4 — The static-export build has been failing since the last SEO commit

**Verified:** `NEXT_PUBLIC_STATIC_EXPORT=true npm run build`, reproducing `.github/workflows/deploy.yml` including its route-removal step.

```
Error: export const dynamic = "force-static"/export const revalidate not configured
       on route "/robots.txt" with "output: export"
Error: Failed to collect page data for /robots.txt
```

**Cause:** `app/robots.ts` and `app/sitemap.ts` were added in `38a4e4d` (the previous SEO pass). Next refuses a metadata route under `output: export` unless it has opted into being static. Neither had.

**Impact:** the GitHub Pages deploy runs on every push to `main` and has failed on all of them since 2026-09-04. The irony is that the commit which added `robots.txt` and `sitemap.xml` is the one that stopped them being published.

**Fix:** `export const dynamic = "force-static"` on both. Both were already build-time-only — `siteIsLive` is an inlined `NEXT_PUBLIC_` value and `getSitemapRoutes()` resolves at build — so this declares existing behaviour rather than changing it.

**Note:** an earlier reading of this as "canonicals and JSON-LD are missing from the export" was wrong. That came from a stale `out/` directory dated 2026-09-01, predating the SEO commits. Corrected by rebuilding.

## Open items actioned

### P1-1 — Title double-branding — **fixed**

| Page | Before | After |
|---|---|---|
| `/` | `Tierney & Ohlms \| Outsourced Accounting & Controller Services · Tierney & Ohlms` (79) | `Outsourced Accounting & Controller Services · Tierney & Ohlms` (60) |
| `/about` | `Our Story \| Tierney & Ohlms · Tierney & Ohlms` (45) | `Our Story · Tierney & Ohlms` (27) |

Service pages were already correct and are unchanged.

Fixed in code rather than content. Editing the CMS values alone would not hold — nothing stops the next editor typing the brand back in. `withoutBrand()` strips a leading or trailing brand before the root template appends its own, so the template is the single owner of the suffix and both current and future values resolve to one mention.

### P1-2 — `ogImage` was an orphaned editor field — **wired; asset still needed**

`ogImage` was fetched in four GROQ projections and read by nothing. An editor could upload a social image, see it saved, and never learn it did nothing.

Now: `seo.ogImage` → `siteSettings.ogImage` → nothing, with `twitter:card` upgrading to `summary_large_image` only when an image actually exists (without one, that card type renders broken). `og:url` is now emitted too, which it previously was not.

A `siteSettings.ogImage` field was added so the default can be supplied without a developer.

**No image is emitted today** because none exists — `public/` is empty and `assets/` holds only two hero photographs. Choosing one as the firm's share card is a brand decision. See the business list.

### Shared metadata helper

All five routes now build metadata through `lib/seo/metadata.ts` instead of five near-identical literals, so canonical, OG title and card type derive from the route and the SEO object rather than being retyped per page.
